# macro_tool — 싱글 플레이 게임용 입력 녹화/재생 (Windows)

Steam 싱글 플레이 게임의 반복 작업(클릭·드래그·키·스크롤)을 녹화하고 재생한다. 현재 **1단계(MVP)**.

## 한눈에 보기
- **녹화·재생**: 마우스(절대/상대 이동)·키보드·스크롤을 녹화하고, 지터·보간·반복 횟수를 정해 재생한다.
- **편집**: 기록 화면에서 이벤트를 고치고, 구간을 반복·만약·동안 반복으로 감싼다.
- **화면 조건**: 이미지(템플릿 매칭)나 범위 색이 나타날 때까지 대기, 이미지 클릭, 변수에 조건을 지정해 흐름 제어에 사용.
- **안전**: 재생 중 오류·중단·창 포커스 이탈 시 눌린 키/버튼을 전부 해제한다.
- **배포**: Python 없이 실행되는 Windows exe(폴더 배포)를 CI가 테스트 후 자동 빌드한다.

## 기술적 특징
- **OpenCV 없이 화면 인식**: 템플릿 매칭(TM_CCOEFF_NORMED와 같은 결과)을 numpy FFT로, PNG 읽기/쓰기를 zlib으로 직접 구현해
  exe 용량을 줄였다. 지난 위치 주변 우선 탐색, 같은 화면 재사용, 축소 후보 탐색으로 판정을 빠르게 한다.
- **화면 캡처**: DXGI Desktop Duplication(COM을 ctypes 가상 함수 표로 호출)을 쓰고, 실패하면 mss로 대체한다.
- **OS 의존 분리**: Windows API는 `input_backend.py`에만 두고, 재생기·녹화기·GUI는 백엔드·시계·캡처를 주입받는다.
  덕분에 Linux에서도 가짜 객체로 단위·GUI 테스트를 돌린다.
- **CI**: Windows에서 테스트 → PyInstaller 빌드 → exe 자가진단(`--selftest`) → artifact/Release 업로드.

## 실행 파일 (.exe)
Python 없이 실행할 수 있다. 배포는 **폴더째**(zip)이며, 압축을 풀면 다음처럼 된다.
```
MacroTool/
  MacroTool.exe   ← 이것을 실행
  _internal/      ← 실행에 필요한 파일 (지우거나 옮기지 말 것)
```
`MacroTool.exe`만 따로 꺼내면 실행되지 않으니 폴더째 쓰기 가능한 곳(예: `문서\MacroTool\`)에 둔다.
매크로(`macros/`)와 설정(`settings.json`)은 **exe와 같은 폴더**에 만들어진다. 게임이 관리자 권한이면 exe도
"관리자 권한으로 실행"한다. 오류로 종료되면 같은 폴더에 `crash.log`가 남는다.

- **GitHub에서 받기**: 저장소 Actions 탭 → `Build Windows exe` → 최근 실행 → Artifacts의 `MacroTool-windows`
  (받은 zip 안의 `MacroTool` 폴더를 사용). `v1.2.0` 같은 태그를 푸시하면 Releases에 `MacroTool-windows.zip`이 올라간다.
  (Windows에서 테스트 → 빌드 → exe 자가진단까지 자동 실행)
- **직접 빌드** (Windows):
  ```
  pip install -r requirements.txt pyinstaller
  python build.py          # -> dist\MacroTool-windows\MacroTool\MacroTool.exe, dist\MacroTool-windows.zip
  dist\MacroTool-windows\MacroTool\MacroTool.exe --selftest   # 점검 결과를 같은 폴더의 selftest.log 에 기록
  ```
- 처음 실행 시 Windows SmartScreen이 "알 수 없는 게시자" 경고를 띄울 수 있다(서명되지 않은 exe). `추가 정보 → 실행`.
- 백신 오탐: 키 입력 후킹·입력 자동화·화면 캡처를 하는 프로그램이라 백신이 의심 파일로 분류할 수 있다
  (예: Defender `Trojan:Win32/Bearfoos.A!ml`, 끝의 `!ml`은 머신러닝 추정 탐지). 이를 줄이려고 단일 exe 대신 폴더 배포,
  직접 컴파일한 PyInstaller 부트로더(CI), exe 버전 정보·아이콘을 쓴다. 그래도 걸리면 폴더를 Defender 제외 목록에 넣거나
  https://www.microsoft.com/wdsi/filesubmission 에 오탐으로 제출한다.

## 설치 / 실행 (소스)
```
pip install -r requirements.txt
python main.py          # GUI (기본)
python main.py --cli    # 콘솔 REPL
```
Windows, Python 3.11+ (tkinter 포함 설치 필요).
게임이 관리자 권한이면 이 도구도 관리자 권한으로 실행해야 한다 (시작 시 경고 표시).

## GUI 사용법
### 메인 화면 — 매크로 목록 / 재생
- 저장된 매크로가 목록(이름, 시작 핫키, 반복, 이벤트 수, 길이, 대상 창)으로 표시된다.
- 선택 후 `▶ 재생`(또는 F9, Enter) → **버튼 시작 지연**(기본 3초) 뒤 시작. 그 사이 게임 창으로 전환한다.
  F9·`■ 중지`로 즉시 멈추며, 진행률·루프·이벤트·경과 시간이 표시된다.
- **매크로별 시작 핫키**를 지정해 두면 게임 안에서 그 키로 바로 재생/중지할 수 있다.
- `+ 추가`(새 매크로) · `편집`(더블클릭) → 기록 화면, `복제`(핫키는 비움), `삭제`(확인 창, Delete 키).
- **매크로 실행 가능/불가**: 오른쪽 위 버튼 또는 **전환 단축키(기본 Ctrl + F12)**로 전체 매크로를 한 번에 켜고 끈다.
  게임 안에서 채팅할 때 끄면 핫키 오작동을 막을 수 있다. 불가 상태에서는 `▶ 재생`·F9·매크로별 시작 핫키가 모두
  동작하지 않고(키는 게임에 그대로 전달), 끄는 순간 재생 중인 매크로도 멈춘다. 기록 화면의 테스트 재생은 가능.
  전환 키는 `단축키 변경`으로 바꾼다 (매크로 핫키·F8~F10과 겹칠 수 없음).
- **상태 오버레이**: 재생(▶ 매크로 이름 · 현재/전체 반복 횟수, 무한은 ∞), 녹화, 시작 카운트다운 중일 때와 전체 실행 전환 직후 2초간
  화면 가장자리에 반투명 표시줄을 띄운다. 위치는 `상태 오버레이 위치`에서 8방향(↖ ↑ ↗ ← → ↙ ↓ ↘) 또는 끄기.
  항상 위에 표시되며 클릭은 아래의 게임 창으로 통과하고 포커스를 가져가지 않는다 (주 모니터 기준).
- 대상을 선택하지 않고 편집/복제/삭제 등을 누르면 아무 동작도 하지 않는다.

### 기록 화면 — 녹화 / 이벤트 편집 / 설정
- **녹화**: `● 녹화`(지연 후 시작) 또는 F8(즉시). F8로 종료하면 녹화된 이벤트가 **목록 끝에 추가**된다.
  카운트다운·녹화 중·테스트 재생 상태는 기록 화면 상단 표시줄에 나온다.
  여러 번 녹화해 이어 붙일 수 있다. 버튼으로 종료하면 그 클릭도 기록되니 F8 권장(기록됐다면 목록에서 삭제).
- **이벤트 목록**: `앞 지연(ms)`(직전 이벤트로부터의 시간), 종류, 내용. 여러 개 선택해 삭제, 더블클릭/`수정`으로 개별 수정,
  `▲ 위로`/`▼ 아래로`로 순서 변경.
- **연속된 마우스 이동은 `마우스 이동 경로` 한 줄**로 묶인다(시작→끝 좌표, 지점 수, 이동 시간). 한 덩어리로 삭제·이동되며,
  수정에서 앞 지연·이동 시간·끝 위치를 바꾸면 경로 전체가 비례 보정된다. 저장·재생 시에는 원래 궤적 그대로 풀린다.
- **이벤트 추가**(선택한 이벤트 뒤, 선택이 없으면 끝):
  `키 입력`(키 입력(누르고 떼기)/키 누름/키 뗌), `마우스`(클릭/누름/뗌/이동/상대 이동/스크롤), `지연`.
  누른 버튼에 해당하는 종류만 대화상자의 종류 목록에 나온다.
  좌표는 직접 입력하거나 `3초 후 현재 위치`로 마우스 위치를 가져온다.
  키는 목록에서 고르거나 **`키 입력으로 지정`**을 누른 뒤 실제 키를 눌러 지정한다.
  `마우스 이동`/`마우스 상대 이동`을 고르면 **`● 이동 녹화`**로 마우스 이동만 녹화할 수 있다
  (카운트다운 후 시작, F9로 종료, 키·클릭은 버리고 이동 경로만 선택한 이벤트 뒤에 추가).
  마우스 클릭·누름·뗌·스크롤은 **`좌표 없이 현재 커서 위치에서 입력`**을 체크하면 커서를 움직이지 않고 버튼만 누른다
  (재생 중 커서는 직접 움직일 수 있다).
- **상대 이동 녹화 (3D 시점 회전)**: 마우스 모드를 `relative`로 두고 녹화하면 커서 좌표 대신 **Raw Input으로 실제
  마우스 이동량**을 녹화한다(`rmove` 이벤트). 게임이 커서를 화면 중앙에 고정해도 시점 회전이 기록되며, 클릭은 좌표 없이
  기록된다. 연속된 이동은 `상대 이동 경로` 한 줄로 묶이고, 수정에서 이동 시간과 **이동량 배율(%)**을 바꿔
  게임 감도 차이를 보정할 수 있다. `마우스 → 마우스 상대 이동`으로 직접 추가도 가능.
- **매크로 설정**: 이름, 시작 핫키, 대상 창 제목, 좌표 기준, 반복 횟수, 속도, 반복 간 대기, 편차, 키 최소 유지 등.
- **🔁 while (반복문)** (`흐름:` 줄 `🔁 while`): 조건 행에서 **횟수**(기본) 또는 이미지/범위 색/변수/여러 조건을 고른다.
  조건을 고르면 아래 "동안 반복"이 되고, **횟수**를 고르면 반복 횟수를 입력해 선택 범위(첫~마지막)를 `반복 시작 ×N` ~
  `반복 끝`으로 감싼다 (선택이 없으면 끝에 빈 구간을 추가하고, 그 사이에 이벤트를 넣는다). 구간 안에 구간을 넣는
  중첩도 된다. 구간 안 이벤트는 `│` 들여쓰기로 표시되고, 요약에 반복을 펼친 예상 시간이 함께 나온다.
  `반복 시작`·`while`을 수정하면 같은 while 창이 열리고, 횟수 ↔ 조건으로 바꾸면 짝이 되는 끝 표시도 함께 바뀐다.
  `반복 끝`을 수정하면 다음 바퀴 전 대기를 바꾼다. 시작이나 끝 하나를 지우면
  짝도 함께 지워지고 안의 이벤트는 남는다. 시작·끝의 순서가 뒤바뀌는 위/아래 이동은 무시된다.
  매크로 전체 반복(`반복 횟수`)과는 별개로 동작한다.
- **되돌리기**: `↶ 되돌리기`/`↷ 다시 실행` 또는 Ctrl+Z / Ctrl+Y(Ctrl+Shift+Z). 이벤트 추가·수정·삭제·이동·녹화 추가를
  최대 100단계까지 되돌린다 (입력란에 커서가 있을 때의 Ctrl+Z는 해당 없음).
- `▶ 테스트 재생`으로 저장 전에 확인하고 `저장`하면 **창이 닫힌다**. 저장하지 않고 닫으면 저장 여부를 묻는다.
- **시작 핫키**: 단일 키(`f6`) 또는 **2키 조합**(`ctrl+f1`, `a+s`). 목록에서 고르거나 직접 입력(`Ctrl + F1`)하거나,
  `키 입력으로 지정`을 누르고 실제 키를 눌러 지정한다. 수정키 조합은 Ctrl 등을 누른 채 F1을 누를 때 실행되고
  (좌/우 Ctrl 구분 없음), 일반 키 두 개 조합은 순서와 상관없이 둘 다 눌리면 실행된다.
  다른 키(이동 중인 W 등)를 누르고 있어도 단일 키 핫키는 동작한다. F8~F10을 포함한 조합은 쓸 수 없다.
- 저장 시 검사: 이름 중복, 핫키 중복/제어 키(F8~F10) 사용, 이벤트에 핫키·제어 키 포함 여부.

## 설정 저장
`settings.json`에 전체 실행 가능/불가 상태, 버튼 시작 지연, 전환 단축키, 메인·기록 화면의 크기와 위치가 저장되어
다음 실행 때 그대로 복원된다 (모니터 구성이 바뀌어 위치가 화면 밖이면 크기만 복원). 지우면 기본값으로 돌아간다.
`settings.json`과 `macros/*.json`은 개인 데이터라 git에 올리지 않는다(`.gitignore`).

## 핫키 (`hotkeys.py` 상수로 변경)
| 키 | 동작 |
|----|------|
| F8 | 녹화 시작/종료 (GUI는 기록 화면이 열려 있을 때) |
| F9 | 재생/중지 (GUI는 목록에서 선택한 매크로) |
| 매크로별 키 | 그 매크로 재생/중지 (GUI 기록 화면에서 지정) |
| F10 | 종료 (눌린 입력 모두 해제 후) |

제어 키는 매크로에 기록되지 않는다.

## REPL 명령 (`--cli`)
`record` · `play` · `stop` · `save <이름>` · `load <이름>` · `delete <이름>` · `list` · `set <옵션> <값>` · `show` · `quit`

| 옵션 | 기본 | 설명 |
|------|------|------|
| `repeat` | 1 | 반복 횟수 (0 = 무한) |
| `speed` | 1.0 | 속도 배율 |
| `loop_delay` | 0 | 반복 사이 대기(초) |
| `time_jitter` | 0 | 대기 시간 ±% 편차 |
| `pos_jitter` | 0 | 클릭 좌표 ±px 편차 (한 번의 클릭/드래그 동안 동일 오프셋) |
| `approach` / `approach_duration` | on / 0.4 | 루프 시작 시 첫 위치까지 가감속 이동 |
| `min_key_hold` | 0.04 | 키 최소 유지 시간(초) |
| `window_title` | (없음) | 이 문자열이 제목에 포함된 창이 포커스일 때만 입력 전송. 녹화 시에는 좌표를 창 기준으로 저장 |
| `mouse_mode` | absolute | `absolute`(절대 좌표) / `relative`(델타 이동, 3D 시점용) |
| `scale_coords` | off | 창 크기가 녹화 때와 다르면 좌표를 비례 조정 |
| `max_minutes` | 0 | 최대 실행 시간(분). 지나면 자동으로 멈춘다 (0 = 제한 없음) |

권장 순서: `set window_title <게임 창 제목>` → F8 녹화 → F8 → `save name` → F9 재생.

## 저장 형식 (JSON)
```json
{"version": 1, "screen": {"width": 1920, "height": 1080},
 "coord_space": "window", "window": {"title": "...", "width": 1280, "height": 720},
 "events": [{"t": 0.0, "type": "move", "x": 10, "y": 20},
            {"t": 0.2, "type": "mdown", "x": 10, "y": 20, "button": "left"},
            {"t": 0.3, "type": "scroll", "x": 10, "y": 20, "dx": 0, "dy": -1},
            {"t": 0.4, "type": "kdown", "key": "w"}]}
```
이벤트 종류: `move`, `rmove`(상대 이동 `dx`, `dy`), `mdown`, `mup`, `scroll`, `kdown`, `kup`, `wait`(지연만),
`repeat_start`(`count`: 0=무한, 1~100000) / `repeat_end`(반복 구간, 짝이 맞아야 하며 중첩 가능),
`wait_until`, `if_start`/`else`/`if_end`, `break_if`, `click_image`, `set_var`, `while_start`/`while_end`
— 아래 "화면 조건", "변수 · 동안 반복 · 여러 조건" 참고.
`mdown`/`mup`/`scroll`은 `x`, `y`를 생략하면 현재 커서 위치에서 입력한다. `hotkey`는 `"f6"`, `"ctrl+f1"` 형식.
GUI로 저장하면 `"hotkey": "f6"`과 `"options": {"repeat": 0, "speed": 1.0, ...}`(재생 옵션)도 함께 저장된다. 드래그는 별도 이벤트 없이 `mdown → move… → mup` 이다.

## 화면 조건 (await · if · break · 이미지 클릭)
화면을 보고 반응하는 기능. 기록 화면의 `흐름:`(if·break)·`조건:`(await·이미지 클릭) 줄에서 추가하고, 목록에서 더블클릭해 수정한다. 주 모니터만 지원한다.

### 🔍 await (조건 대기)

- **이미지가 보일 때**: `📷 화면에서 잘라내기` → (버튼 시작 지연 동안 게임 화면으로 전환) → 캡처된 화면에서 찾을 부분을
  드래그한다. 잘라낸 이미지와, 그 주변으로 여유를 둔 **검색 영역**이 자동으로 채워진다(`검색 영역만 다시 지정`,
  `화면 전체에서 찾기`로 변경 가능). `일치도 기준(%)` 이상이면 충족(기본 85%).
- **범위의 색이 맞을 때**: `🎨 범위를 드래그해 색 선택` → 캡처된 화면에서 범위(예: 체력바, 버튼)를 드래그하면
  그 범위에서 **가장 많이 차지하는 색**이 목표 색으로 채워지고, 그 색이 범위의 몇 %인지 표시된다.
  판정: 범위 안에서 목표 색(채널별 `허용 오차`, 기본 20 이내)인 픽셀이 `이 색의 비율`(기본 50%) 이상이면 충족.
  한 점만 보려면 너비·높이를 1로 둔다.
- `반대로`: 조건이 "아닐" 때까지 대기 (예: 로딩 화면이 사라질 때까지).
- `최대 대기(초, 0=무제한)`, `시간 초과 시`: **재생 중지**(기본) 또는 **계속 진행**. `확인 간격(ms)`: 기본 100ms.
- `🔍 지금 찾아보기`: 지연 후 현재 화면에서 바로 판정해 충족 여부·일치도·찾은 위치를 보여준다(기준값 정할 때 사용).
- 조건이 맞을 때까지 기다린 시간만큼 이후 이벤트가 뒤로 밀린다(이벤트 사이 간격은 유지).
- 조건 이미지는 `macros/<매크로 이름>/`에 PNG로 저장되며, 이름 변경·복제·삭제 시 함께 처리된다.
  기록 화면에서는 임시 폴더에서 작업하므로 저장 전 테스트 재생에도 새 이미지가 쓰이고, 저장하지 않고 닫으면 버려진다.
  재생 시작 전에 이미지가 모두 있는지 확인한다. 좌표는 매크로의 좌표 기준(화면/창)을 따른다.
- 필요 패키지: `mss`, `numpy` (requirements.txt). 이미지 찾기와 PNG 입출력은 numpy 로 직접 구현해 OpenCV 가 필요 없다.
- 판정 속도: 화면 캡처는 DXGI 데스크톱 복제를 쓰고(안 되면 mss/GDI 로 자동 전환), 이미지 조건은 지난번 찾은 위치
  주변부터 확인한다. 영역 화면이 지난번과 똑같으면 다시 계산하지 않고, 넓은 영역은 줄인 화면에서 후보를 찾은 뒤
  후보 주변만 원본 크기로 확인한다. 여러 조건은 가까운 영역을 한 번에 캡처한다.

### if · break · 이미지 클릭
흐름 제어(if·break·while)의 조건도 **이미지 / 범위 색 / 변수 / 여러 조건** 중에서 바로 고른다.
같은 화면 판정을 여러 곳에서 쓸 때는 `📌 const`로 변수에 담아 쓰면 편하다(아래 "변수 · 동안 반복 · 여러 조건").

- **❓ if (조건 분기)**: 이벤트를 선택하고 누르면 `❓ if [조건]` ~ `❓ if 끝`으로 감싼다. `'else' 구간도 만들기`를
  체크하면 `↪ else`가 추가되고, 그 아래에 넣은 이벤트는 조건이 맞지 않을 때 실행된다(`else` 줄을 선택하고 추가).
  조건은 그 시점에 한 번 판정한다. `if`나 `if 끝`을 지우면 짝이 함께 지워지고, `else`만 따로 지울 수도 있다.
  반복 구간과 서로 중첩할 수 있다(엇갈리면 저장 불가).
- **⏹ break (반복 탈출)**: 조건이 맞으면 가장 안쪽 반복 구간을 끝내고 그 다음으로 진행한다(구간 밖이면 이번 회차를 끝낸다).
  반복문 횟수를 **0(무한)**으로 두고 함께 쓰면 "~가 보일 때까지 반복"이 된다.
- **🖱 이미지 클릭**: 이미지가 보일 때까지 기다렸다가 찾은 위치의 중앙(+`보정 X, Y`)을 지정한 버튼으로 클릭한다.
  최대 대기·시간 초과 시 동작은 await와 같고, 클릭 좌표 편차 옵션이 적용된다.

JSON 형식:
```json
{"t": 1.2, "type": "wait_until", "timeout": 10, "on_timeout": "stop", "interval": 0.1,
 "cond": {"kind": "image", "template": "이미지1.png", "region": [600, 400, 300, 150], "threshold": 0.85}}
{"t": 2.0, "type": "wait_until", "timeout": 0, "on_timeout": "continue",
 "cond": {"kind": "pixel", "x": 120, "y": 40, "w": 200, "h": 12, "color": "#d03030", "tolerance": 20,
          "ratio": 0.5, "negate": true}}
{"t": 2.5, "type": "if_start", "cond": {...}}  ...  {"t": 3, "type": "else"}  ...  {"t": 3.5, "type": "if_end"}
{"t": 4.0, "type": "break_if", "cond": {...}}
{"t": 4.5, "type": "click_image", "cond": {"kind": "image", "template": "확인.png"}, "button": "left",
 "offset": [0, 5], "hold": 0.06, "timeout": 10, "on_timeout": "stop"}
```

## 변수 · 동안 반복 · 여러 조건
조건을 부품처럼 조립하는 기능. const·await·흐름 제어(while·if·break)는 모두
**이미지 / 범위 색 / 변수 / 여러 조건**을 고른다(이미지 클릭은 이미지만).

- **📌 const (변수 저장)** (`변수:` 줄): 조건(화면 판정 등)을 이름 붙인 변수에 **지정**한다. 이 줄에서는 판정하지 않는다.
  같은 화면 판정을 여러 곳(흐름 제어 등)에서 쓸 때 쓴다.
  변수 이름은 글자·숫자·`_` 1~20자. 아직 지정되지 않은 변수는 거짓이다. 같은 이름을 다시 지정하면 그 뒤로는 새 조건을 쓴다.
- **변수 조건**: 변수가 **쓰일 때마다** 지정된 조건을 그 자리에서 판정해 참이면 충족(`반대로`로 거짓일 때).
  예) while의 조건에 쓰면 바퀴마다 화면을 다시 본다.
  조건에서 쓰는 변수를 지정하는 `const` 항목이 없으면 저장할 수 없다.
- **여러 조건**: `추가…`로 조건(이미지/범위 색/변수)을 2개 이상 넣고 `모두 맞을 때(그리고)` 또는
  `하나라도 맞을 때(또는)`를 고른다. 앞에서 결과가 정해지면 뒤 조건은 판정하지 않는다. 여러 조건 안에 여러 조건은 넣을 수 없다.
- **🔂 while (동안 반복)** (`흐름:` 줄 `🔁 while`에서 횟수 외의 조건 선택): 선택한 이벤트를 `🔂 while [조건]` ~ `🔂 while 끝`으로 감싼다.
  매 회차 시작 전에 조건을 판정해 맞는 동안 반복한다. 안의 `⏹ break`는 가장 안쪽 반복(반복 구간/동안 반복)을 끝낸다.
  한 바퀴에 지연이 없어도 최소 10ms 간격을 둔다.
- **변수 초기화**: 재생 회차마다 지정이 비워진다(지정 전에 쓰이면 거짓). 자기 자신을 다시 참조하는 변수는 거짓이다.
- `지금 찾아보기`는 기록 화면의 `const` 지정(같은 이름이면 마지막 것)으로 변수를 판정하고, 지정 안 된 변수는 거짓으로 본다.

JSON 형식:
```json
{"t": 0.5, "type": "set_var", "name": "보스", "cond": {"kind": "image", "template": "boss.png"}}
{"t": 0.6, "type": "while_start", "cond": {"kind": "all", "conds": [
   {"kind": "var", "name": "보스"}, {"kind": "pixel", "x": 50, "y": 20, "color": "#d03030"}]}}
  ...
{"t": 1.0, "type": "while_end"}
```

## 이미지 변수
이미지에 이름을 붙여 두고, 이미지 조건(await·if·break·while·const·여러 조건)과 이미지 클릭에서
`찾을 이미지: 이미지 변수`로 골라 쓴다. 기록 화면 `변수:` 줄의 `🖼 이미지 변수`로 추가한다.

- **잘라낸 이미지 (고정)**: `📷 화면에서 잘라내기`로 자른 이미지를 이름으로 담는다. 같은 이미지를 여러 곳에서 쓸 때,
  이미지를 바꾸면 이 항목 하나만 고치면 된다. 조건 창에서 고르면 미리보기가 나오고 `지금 찾아보기`에도 쓰인다.
- **재생 중 화면 캡처**: 재생 중 이 항목에 도달한 순간 지정한 영역(`영역 드래그` 또는 X·Y·너비·높이)을 캡처해 담는다.
  예) 시작할 때 화면 일부를 기억해 두고, 같은 영역에서 그 이미지가 `반대로`(안 보이면) `⏹ break` → "화면이 바뀔 때까지 반복".
  편집 화면에서는 내용을 알 수 없어 `지금 찾아보기`에서는 거짓으로 본다. 영역이 화면 밖이면 지정되지 않는다.
- 다른 변수처럼 **재생 회차마다 비워지고**, 지정 전에 쓰이면 찾지 못한 것(거짓)으로 본다. 같은 이름을 다시 지정하면 그 뒤로는
  새 이미지를 쓴다. 조건에서 쓰는 이미지 변수를 지정하는 항목이 없으면 저장할 수 없다.
- 이미지 조건의 검색 영역을 정하지 않고 이미지 변수를 고르면 `화면 전체에서 찾기`가 켜진다.
- 단색 이미지(모든 픽셀이 같은 색)는 일치도를 계산할 수 없어 찾지 못한다. 색만 볼 때는 범위 색 조건을 쓴다.

JSON 형식:
```json
{"t": 0.0, "type": "set_image", "name": "확인", "template": "이미지1.png"}
{"t": 0.0, "type": "set_image", "name": "처음", "capture": [600, 400, 120, 40]}
{"t": 0.5, "type": "break_if", "cond": {"kind": "image", "image_var": "처음", "region": [600, 400, 120, 40],
                                       "negate": true}}
{"t": 0.8, "type": "click_image", "cond": {"kind": "image", "image_var": "확인"}, "button": "left"}
```

## 알려진 한계
- 독점 전체 화면 모드보다 **창 모드/테두리 없는 창 모드**가 안정적이다.
- **상대 이동 모드**는 게임의 마우스 감도·가속 설정과 Windows "포인터 정확도 향상" 설정에 따라 재현 결과가 달라질 수 있다
  (이동량 배율로 보정). Raw Input 녹화는 GUI 기록 화면에서 마우스 모드가 `relative`일 때만 쓰인다.
- 상태 오버레이는 독점 전체 화면 게임 위에는 표시되지 않을 수 있다 (창 모드/테두리 없는 창 모드 권장).
- **안티치트**가 있는 게임은 입력 자동화를 차단하거나 제재할 수 있으므로 사용 전 확인이 필요하다.
- 창 포커스를 잃으면 눌린 입력을 해제하고 일시정지하며, 복귀 후에는 끊긴 지점부터 이어가지만 도중에 풀린 드래그는 복원되지 않는다.
- 텐키 Enter는 일반 Enter로 기록된다. 한/영·IME 전환 키는 지원하지 않는다.
- 실제 Windows 환경에서의 `SendInput` 동작은 이 저장소의 CI/Linux 테스트로 검증되지 않았다(백엔드는 의도적으로 얇게 유지).
